◆ dbgId_t

enum dbgId_t

Encodes the debug point IDs used in the RSDK.

Intended to be passed as arguments to DBG_POINT(), to integrate debugger support for file I/O and multicore debug control operations.

Enumerator
DBG_ID_FREAD 

signals to the debugger that a system file read is expected

DBG_ID_FWRITE 

signals to the debugger that a system file write is expected

DBG_ID_FCOMP 

tells the debugger to compare content in platform memory with a file on the PC

DBG_ID_PRINT 

for printing a message on the debug console

DBG_ID_TESTCASE_END 

signals the end of a test case. Useful for test automation actions (e.g. saving console output)

DBG_ID_SESSION_END 

signals the end of a test session. Useful for test automation actions (e.g. saving console output)

DBG_ID_HALT_ERROR 

signals an execution error condition

DBG_ID_SESSION_START 

signals the start of a test session. Useful for test automation actions (e.g. detecting if test has been launched successfully based on console output)

DBG_ID_LB_PROFILING_REINIT 

signals Lauterbach trace reinitialization (flushes already collected data)

DBG_ID_LB_PROFILING_RESUME 

signals Lauterbach trace start

DBG_ID_LB_PROFILING_PAUSE 

signals Lauterbach trace stop

DBG_ID_LB_PROFILING_PRINT 

signals Lauterbach trace output to file

DBG_ID_LB_BRKPT 

signals Lauterbach breakpoint

DBG_ID_OTHER

◆ DBG_POINT()

dbgId_t DBG_POINT ( dbgId_t  ID)

Allows interaction with Lauterbach debug scripts (.cmm) that are included in RSDK package.

This function simply defines an elf symbol onto which a breakpoint can be attached. It does not do any processing. Once the breakpoint is hit, the debugger can take different actions, based on the debug point ID.

Parameters
[in]ID- debug point ID chosen from dbgId_t enumeration

◆ DbgInit()

rsdkStatus_t DbgInit ( const char *  iniFile)

Perform debug related initialization operations.

Must be invoked on all cores where file I/O operations would be then performed. The file I/O method is selected at compile time by a set of preprocessor macros. See 3.5 Preprocessor defines for details.

Precondition
In case TFTP support is needed on the Z7 core, then both the Z4 and Z7 ELFs must include proxy_intercom.c source file from rsdk/Tools/Debug_tools and a rsdkProxy_t typed variable must be defined by the application in a memory area that is shared between the server and client sides of this proxy (eg .data_shared for Z4 and Z7 cores)
Accesses to this variable are guarded by PROXY_BUSY_SEMA, defined at compile time, in proxy_intercom.c See /Apps/1RF_4Antennas_demo and proxy_intercom.h for more details
Parameters
[in]iniFile- String pointing to TFTP configuration file. Can be left NULL if TFTP is not used and for PROXY_CLIENT_FILEIO mode. Configuration of TFTP client/server is done via this file, containing, eg:
# TFTP CLIENT MAC and IP (ie. this RRU board)
00:11:33:55:77:AA
192.168.1.112
# alternatively, IP address can be written as 0xC0A80170

# TFTP SERVER MAC and IP (could be any TFTP server, eg. OpenTFTPServer)
00:50:56:AF:7E:D2 (set to FF:FF:FF:FF:FF:FF) to have ARP take care of this
192.168.1.110
# alternatively, IP address can be written as 0xC0A8016E

# TFTP SERVER PORT
69

# (optional) PREPENDED PATH
# if present, this represents a file path that is prepended to all
# filename requested via TFTP services. It can be used to adapt the
# root folder of the TFTP server running on the host PC to the proper
# folder in the application being executed.
dir/subdir/
Returns
Operation result

◆ DbgPerformMemTransformOper()

rsdkStatus_t DbgPerformMemTransformOper ( char *  bufAddr,
int32_t  bufSize,
const char *  memTransformOper,
bool  isCacheable 
)

Perform cross-endian transformation on a buffer in memory.

Note
Halts execution is called with wrong input parameters
Parameters
[in]bufAddr- Starting address of memory buffer
[in]bufSize- Size of memory buffer
[in]memTransformOper- Operation to be performed on the memory buffer
"none" for no transformation, i.e. byte-to-byte I/O
"word16" for swapping bytes of int16, i.e. cross-endian on int16_t
(byte0-byte1 -> byte1-byte0)
"word32" for swapping bytes of int32, i.e. cross-endian on int32_t
(byte0-byte1-byte2-byte3 -> byte3-byte2-byte1-byte0)
"word64" for swapping bytes of int64, i.e. cross-endian on int64_t
(byte 0-1-2-3-4-5-6-7 -> byte 7-6-5-4-3-2-1-0)
[in]isCacheable- If the buffer is cacheable, then the function will ensure coherency in system memory by performing flush/invalidate operations.
Returns
status of performed operation

Perform file i/o read operation.

Precondition
DbgInit() must be called before using this function. The code must be built with a valid combination of preprocessor macros (see DbgInit() description)
Parameters
[in]fileName- String containing file to be read
[in]offsetBytes- Number of bytes to skip at the beginning of the file (to mimic fseek() in SEEK_SET mode). Can be 0 or a positive integer
[in]destAddr- Pointer to SRAM where read bytes are to be stored. Mind to have a server-client shared memory zone when using PROXY_CLIENT_FILEIO mode
[in]maxBytes- Max number of bytes to read
Returns

◆ DbgSendRtp()

void DbgSendRtp ( const char *  srcAddr,
int  numBytes,
uint32_t  timestamp,
uint8_t  payload_type,
uint32_t  ssrc 
)

Send a RTP/UDP stream using source port 7777 and destination 7778. Sequence number starts from 55193 and is automatically incremented with each sent packet.

Precondition
DbgInit() must be called before using this function with Ethernet properly configured.
Parameters
[in]srcAddr- Pointer to SRAM from where bytes are sent. Mind to have a server-client shared memory zone when using PROXY_CLIENT_FILEIO mode
[in]numBytes- Number of bytes to send (0 is a valid value)
[in]timestamp- As defined by RTP protocol
[in]payload_type- As defined by RTP protocol
[in]ssrc- As defined by RTP protocol
Note
This is a blocking operation, ie. control is returned only after whole stream is sent.
