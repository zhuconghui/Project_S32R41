Detailed Description

RFE Abstract 2.0 constants for the specific structure for Front-End configuration.

Here we describe the RFE configuration binary object (blob) which is to be provided as input to rfe_configure() API function. The blob consists of multiple memory sections as shown in the below table. The RFE Configuration BLOB can be created by the RFE configuration generator. The functions in rfe_blob_access.h are used to retrieve or update the blob configuration data at run time. After local manipulation, (i.e. updating the blob in the platform memory) the configuration needs to be reloaded to the RFE by calling rfe_configure(). This will reconfigure and calibrate the full RFE, which takes in the order of tens of milliseconds depending on the amount of chirp profiles used. To update a subset of RFE parameters in a timely manner (tens of microseconds) it is recommend to use the rfe_update.h functions. These updates can even take place when the radar cycle is active, during the radar cycle idle time.

general 1 Contains the general parameters
monitorAndSafety 1 Contains the monitor and safety parameters

powerMode

Selects the powerMode of the rfe:

  • 0: lower power
  • 1: active
Warning
If a sequence uses multiple profiles with different TXs enabled (see txTransmissionEnable), this setting must be configured to "lower power" otherwise a lock-step error would be triggered from ISM.

pdcDecimationFilter

Selects the decimation filter of the programmable decimation chain. This option reduces the effective sampling rate of the ADC as follows:

  • 0: Narrow bandwidth with a passband response up to 0.4 x fEFFECTIVE_SAMPLE_RATE.
  • 1: Wide bandwidth with a passband response up to 0.5 x fEFFECTIVE_SAMPLE_RATE.
Remarks
For a detailed description, please refer to the Reference Manual (RM00227), chapter "Programmable decimation chain".

jumpbackTimeTicks

The chirp jumpback time for all chirps in 25 [ns] resolution.

txCalibration

Configures whether the TX antennas will perform calibration with normal radiation levels, or significantly reduced radiation levels.
In case of calibration with reduced transmission radiation, the txCalibration_thresholdHigh and txCalibration_thresholdLow must also be set.

Remarks
Default value: 1 (i.e. with transmission, if omitted from XML when generating)

frequencyForBist

The center frequency in kHz, to be used for RX BIST.

zeroHrRefForRxPhaseDiffLna

Reference signal phase difference of all RX channels against the 1st RX (in degrees, for LNA input. See injectTestTone).

Remarks
  1. The RX BIST is for the fixed combination RX1-RX2, RX1-RX3 and RX1-RX4.
  2. The RX BIST will be executed for enabled RX channels for the combination mentioned above.
  3. The RX BIST will be skipped if RX1 is not enabled.

rxPhaseDiffLnaThresholdTolerance

The allowed difference between the measured RX to RX phase difference and the zero hour data (in degrees, for LNA input. See injectTestTone). If the measured value exceeds the threshold for any of the measured combinations (RX1-RX2, RX1-RX3 and RX1-RX4), the RX BIST will be marked as failed and ERROR_N will be asserted.

If the measured value exceeds the threshold for any of the measured combinations (RX1-RX2, RX1-RX3 and RX1-RX4), the RX BIST will be marked as failed and ERROR_N will be asserted.

Remarks
  1. The RX BIST is for the fixed combination RX1-RX2, RX1-RX3 and RX1-RX4.
  2. The RX BIST will be executed for enabled RX channels for the combination mentioned above.
  3. The RX BIST will be skipped if RX1 is not enabled.

injectTestTone

Configures the injection point of the test tone during RX BIST. When injectTestTone is set to 0, the test tone is injected twice every RX BIST sequence, once before LNA & once before Mixer. when injectTestTone is set to 1, the test tone is injected every RX BIST sequence only before Mixer. when injectTestTone is set to 2, injection point of the test tone repeatedly alternates between before LNA and before Mixer with each RX BIST sequence.

checkBbd_loi

Configures the following settings, bitwise encoded:

  • 0001 0000 : Enables/Disables the Ball Break detector for LO Interface.
  • 0000 1000 : High/Normal current sensitivity for the LO-out Ball Break detector.
  • 0000 0100 : Grounded/Not Grounded Ball Break detector balun, for the LO-out.
  • 0000 0010 : High/Normal current sensitivity for the LO-in Ball Break detector.
  • 0000 0001 : Grounded/Not Grounded Ball Break detector balun, for the LO-in.

checkBbd_tx

Configures the following settings, bitwise encoded:

  • 0000 0100 : Enables/Disables the Ball Break detector for TX antennas.
  • 0000 0010 : High/Normal current sensitivity for the TX antennas Ball Break detector.
  • 0000 0001 : Grounded/Not Grounded Ball Break detector balun, for the TX antennas Ball.

checkBbd_rx

Configures the following settings, bitwise encoded:

  • 0000 0100 : Enables/Disables the Ball Break detector for RX antennas.
  • 0000 0010 : High/Normal current sensitivity for the RX antennas Ball Break detector.
  • 0000 0001 : Grounded/Not Grounded Ball Break detector balun, for the RX antennas Ball.

fuSaFaultMask

Functional safety faults to be masked/unmasked. Masked faults do not assert the ERROR_N signal.
The enumeration from rfe_fuSaFault_t must be used as bitwise index to mask or unmask the corresponding fault. To mask, set the desired bit to ‘1’, to unmask, set to ‘0’.

Remarks
  • NXP does not recommend the user to mask the faults, as they will not be detected, which may violate the safety goal.
  • rfe_generic_sw_e - is a generic software error that is raised by any rfe_error_t triggered, therefore it cannot be masked! It is kept however in this list for visibility.

radarCycleDuration

Radar cycle duration in 25 [ns] resolution.

chirpSequenceCount

Number of chirp sequences configured for the radar cycle.

chirpSequence

Contains the chirp sequence configurations, in the order they were configured in the XML at generation time.
Based on chirpSequenceCount, how many of the rfeCfg_param_radarCycle_chirpSequence_0_e --> rfeCfg_param_radarCycle_chirpSequence_7_e contain
a configuration that is intended to be used in the radar cycle.

chirpSequenceStartTimeOffset

The chirp sequence time offset in 25 [ns] resolution with respect to the start time of the radar cycle. The offset is defined as the time difference between the start of the dwell time of the first chirp and the start time of the radar cycle.
If using powerMode = 1, then an additional DC_Power_on_Delay value in the order of hundreds of microseconds will be added before the dwell time of the first chirp. The start time of chirp sequence 0 is fixed at design time. For the first sequence in the radar cycle, the time checking is disabled because the init chirp sequence and recalibration may take longer, otherwise the timing will not be optimal for the radar system.

bistInterval

The interval to perform RFE built-in-self-tests. The selections are:

  • 0 : No BIST.
  • 1 : Every radar cycle. (recommended)
  • 2 : Once in two radar cycles.
  • 3 : Once in four radar cycles. The rationale is that RX BIST must be executed once per Fault Handling Time Interval (FHTI). FHTI is associated with 1 radar cycle in radar safety concept. Doing it less often than 1 radar cycle is not recommended. For more information on RX BIST and FHTI relation please refer to Functional Safety Manual.

The number of chirps within the chirp sequence.

chirpProfileSequence

The list of profiles that are used for the current sequence, and their order. Based on the chirpProfileSequenceLength, determines how many profiles should be considered, and how many should be ignored,
from the list rfeCfg_param_chirpSequence_chirpProfileSequence_0_e --> rfeCfg_param_chirpSequence_chirpProfileSequence_7_e.

chirpProfileSequenceLength

The number of chirp profiles, that are configured for the current sequence.
This parameter determines how many rfeCfg_param_chirpSequence_chirpProfileSequence_0_e --> rfeCfg_param_chirpSequence_chirpProfileSequence_7_e should be used, and which should be ignored.

chirpProfileRepeatCount

Configures the number of times a profile will be repeated within the chirp sequence, before switching to the next profile in the list (e.g. using profileRepeatCount = 3, and chirpProfileSequence = "0 1 2" will result in the following profiles being used: 0, 0, 0, 1, 1, 1, 2, 2, 2. Otherwise, with profileRepeatCount = 1 -> 0, 1, 2, 0, 1, 2, 0, 1, 2.

  • Example 1: Chirp sequence: 0-0-0-0-0-0-..
    chirpProfileSequence = {rfe_chirpProfileIndex_0_e};
    chirpProfileRepeatCount = 1;
  • Example 2: Chirp sequence: 1-1-1-1-1-1-..
    chirpProfileSequence = {rfe_chirpProfileIndex_1_e};
    chirpProfileRepeatCount = 1;
  • Example 3: Interleaved chirp sequence 0-0-0-1-1-1-2-2-2..
    chirpProfileSequence = {rfe_chirpProfileIndex_0_e, rfe_chirpProfileIndex_1_e, rfe_chirpProfileIndex_2_e};
    chirpProfileRepeatCount = 3;
  • Example 4: Interleaved chirp sequence 0-1-2-0-1-2-0-1-2..
    chirpProfileSequence = {rfe_chirpProfileIndex_0_e, rfe_chirpProfileIndex_1_e, rfe_chirpProfileIndex_2_e};
    chirpProfileRepeatCount = 1;

dynamicUpdatesEnabled

Sets whether the dynamic updates, i.e. parameter updates per chirp, are enabled or disabled.

dynamicTableIndex

The index of the dynamic table to be used for the chirp sequence. This table contains the values for each dynamic parameter for each chirp.

txPhaseRotation_ddma

Configures the DDMA control mode. Values are:

  • 0: disabled
  • 1: functional mode
  • 2: test mode (phase code step is incremented during chirp @ 40 MHz)
  • 3: test no chirp DDMA test mode with non-chirp mode (phase code step is incremented during chirp @ 40 MHz)

txPhaseRotation_ddma_tx

  • 0000 0001 (TX1): 0 -> Phase code is taken from Profile | 1 -> Phase code is taken from DDMA generator.
  • 0000 0010 (TX2): 0 -> Phase code is taken from Profile | 1 -> Phase code is taken from DDMA generator.
  • 0000 0100 (TX3): 0 -> Phase code is taken from Profile | 1 -> Phase code is taken from DDMA generator.

txPhaseRotation_ddma_tx1_init

Configures the PR DDMA initial phase for TX 1. (in steps of 5.625 degrees).

Remarks
A similar parameter exists for TX2 & TX3.

txPhaseRotation_ddma_tx1_update

Configures the PR DDMA phase increment for TX 1. (in steps of 5.625 degrees).

Remarks
A similar parameter exists for TX2 & TX3.

txPhaseRotation_ddma_tx1_mode

Configures how the phase code is generated for TX 1. Values are:

  • 0: No change to phase code.
  • 1: Replace two MSB bits of phase code with the QPSK[1:0] bits
  • 2: Add the QPSK[1:0] bits to two MSB bits of initial phase code
    Remarks
    A similar parameter exists for TX2 & TX3.

  • 0000 0001 : RX1 Enabled/Disabled
  • 0000 0010 : RX2 Enabled/Disabled
  • 0000 0100 : RX3 Enabled/Disabled
  • 0000 1000 : RX4 Enabled/Disabled

Values coming from the blob are in dB, multiplied by 100 to account for 2 digits. [0.01 .. 4] This setting is only valid when txCalibration is set to 0.

effectiveSamplingFrequency

The effective sampling frequency of the chirp. Here 'effective' indicates that this is the sampling frequency after decimation, i.e. of the output samples.

chirpIntervalTimeTicks

The chirp interval time in 25 [ns] resolution. It is the time between the start of subsequent chirps and this parameter can be used to introduce additional idle time between chirps. The value for this parameter must be equal or larger than the sum of its components: dwellTimeTicks, settleTimeTicks, acquisitionTimeTicks, jumpbackTimeTicks, and resetTimeTicks.

dwellTimeTicks

The chirp dwell time in 25 [ns] resolution.

settleTimeTicks

The chirp settle time in 25 [ns] resolution.

acquisitionTimeTicks

The chirp acquisition time in 25 [ns] resolution.

resetTimeTicks

The chirp reset time in 25 [ns] resolution.

centerFrequency

The center frequency of the chirp in [kHz].

effectiveChirpBandwidth

The effective bandwidth in [kHz]. This is the bandwidth used during the chirp acquisition. A bandwidth of 0 results in a 'chirp' with constant frequency. The actual effective chirp bandwidth is rounded to a multiple of acquisitionTimeTicks * RFE_CHIRP_FREQUENCY_DRIFT_STEPS_HZ.

chirpPllVcoSelect

Selection of the VCO that the chirp PLL uses to generate the chirp:

  • 0: 1GHz VCO
  • 1: 2GHz VCO
  • 2: 4GHz VCO

chirpSlopeDirection

Selection of the direction of the chirp slope: rising or falling.

chirpPllLoopFilterBandwidth

Selects the chirp PLL loop filter bandwidth.
See rfe_chirpPllLoopFilterBandwidth_t for all the values.

Attention
Values that can be selected, depend on the VCO parameter from above. In order to achieve the highest recommended chirp steepness per VCO, the values below are sugested, which also ensure the lowest phase noise:
  • For 1GHz VCO -> 200kHz | 250kHz | 300kHz
  • For 2GHz VCO -> 250kHz | 300kHz
  • For 4GHz VCO -> 300kHz | 350kHz

txTransmissionEnable

Selection of transmitters that transmit the chirp.

  • 0000 0001 : TX1 Enabled/Disabled
  • 0000 0010 : TX2 Enabled/Disabled
  • 0000 0100 : TX3 Enabled/Disabled
Warning
If a Sequence uses multiple profiles, that has different TXs enabled, then powerMode must be configured to 0 ("lower power") otherwise a lock-step error would be triggered from ISM.

txPower

Output power of the transmitters in the steps of 0.1 [dBm]. The value coming from the blob is multiplied by 10, to account for the 1 decimal.

txPhaseRotation

Phase rotation for each transmitter (in steps of 5.625 degrees).

chirpFrequencyDriftSteps

The frequency of the chirp (i.e., start & end frequency of the chirp frequency sweep) increments (positive) or decrements (negative) by x * 42.9153 Hz each chirp, after chirp 1. A value of 0 will disable the drift. Values other than 0 are not supported, when the chirp sequence consists of chirps with different Center Frequencies (i.e. center-frequency-kHz)

Remarks
When chirpFrequencyDriftSteps is enabled (i.e. value != 0), if using different centerFrequency in the same sequence,
the first centerFrequency value will be used, and the rest will be ignored. Front-End will issue no warning for such case.

rxGain

The gain of the receivers. Values are:

  • 1: 27dB
  • 2: 30dB
  • 3: 33dB
  • 4: 36dB
  • 5: 39dB
  • 6: 42dB
  • 7: 45dB

rxHpfCutOffFrequency

The cut-off frequency of receivers' high-pass filters:

  • 0: 100 kHz
  • 1: 200 kHz
  • 2: 300 kHz
  • 3: 400 kHz
  • 4: 800 kHz
  • 5: 1600 kHz
  • 6: 3200 kHz

rxLpfCutOffFrequency

The cut-off frequency of receivers' low-pass filters.

  • 0: 15 MHz
  • 1: 20 MHz
  • 2: 25 MHz
  • 3: 40 MHz

virtualChannel

The virtual channel applied on data for the chirps using this profile.
