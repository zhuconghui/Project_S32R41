void RsdkBbe32CaCfar ( uintptr_t  argList)

1D CA-CFAR implementation iso-doppler dimension Using sliding window approach to avoid redundant summations.

Parameters
[in]argList- pointer to a data structure of type rsdkBbe32CaCfarParams_t containing the CA-CFAR parameters and buffers.
Precondition
This implementation assumes the following memory layout of the input RDM buffer passed by rsdkBbe32CfarParams_t::pRdm :

INPUT Memory layout example for RangeBins = Nr, DopplerBins = Nd: Sample format: 16 bit real SPT "Log2 Mag2"

offset bytes: 0 2 ... 2*(Nd-2) 2*(Nd-1)
0 R0_D0 R0_D1 ... R0_D<Nd-1> R0_D<Nd>
2*Nd R1_D0 R1_D1 ... R1_D<Nd-1> R1_D<Nd>
: : : :
: : : :
2*(Nr-1)*Nd R<Nr>_D0 R1<Nr>_D1 ... R1<Nr>_D<Nd-1> R1<Nr>_D<Nd>

◆ RsdkBbe32Doa128()

void RsdkBbe32Doa128 ( uintptr_t  argList)

DoA 128 24bits complex input.

Performs DoA based on FFT128 on 24bits on complex operands. The algorihm extends an input vector to 128 complex elements(fill with 0), applies the corresponding FFT and computes the mag2 => (real^2 + imag^2)/2.
Using these values, the maximum mag2 value is computed and multiplied with a threshold factor obtaining a threshold value.
This result is then compared with all the local maximum values(localMaxMag2 > threshold) of the mag2 for creating a bitmap.
A value mag2(i) is considered a local maximum value if (mag2(i) > mag2(i - 1) and mag2(i) >= mag2(i+1)).
The start and the end of the resulting mag2 vector are not considered.

Parameters
[in]argList- pointer to a data structure of type rsdkBbe32DoaParams_t containing the DoA parameters and buffers.
Precondition
RsdkBbe32FftInit() must be called for initializing FFT window and twiddles coefficients before calling this function the same size parameter.
The pOutMag an pIn are pointers to the real mag2 output and complex input data respectively, which use int32_t.
Even though the operations are performed on 24bits (re, imag), the data is stored in memory on 32 bits. The outputs are sign extended to 32 bits.
The pDetectBitmap contains the resulting bitmap and is represented using uint16_t.
The shift value should be RSDK_BBE32_FFT_SHIFT_2 since a division by 4 is required before performing each radix4/radix2 round to prevent saturation.
The available sizes are described in rsdkBbe32FftSize_t enum.
The output signals should be scaled with (shift_value^4)^2 / 256.
The twiddles and window coeffi are converted inside the used FFT kernel from q0.15 to q0.23 fixed point.

◆ RsdkBbe32Fft2Real()

void RsdkBbe32Fft2Real ( uintptr_t  argList)

FFT 24bits 2 real inputs.

Performs FFT on 24bits 2 real operands in 1 complex operand. Lower half of each Fft is returned.

Parameters
[in]argList- pointer to a data structure of type rsdkBbe32Fft2RealParams_t containing the FFT parameters and buffers.
Precondition
RsdkBbe32FftInit() must be called for initializing FFT window and twiddles coefficients before calling this function the same size parameter.


The pOut1 an pOut2 are pointers that serve both as two output complex lower half FFTs(one for each signal) and uses int32_t.
Even though the operations are performed on 24bits (re, imag), the data is stored in memory on 32 bits. The outputs are sign extended to 32 bits.
The shift value should be RSDK_BBE32_FFT_SHIFT_2 since a division by 4 is required before performing each radix4/radix2 round to prevent saturation.
The available sizes are described in rsdkBbe32FftSize_t enum.
OPTIONAL: For maintaining the accuracy of the results, the two output FFTs can be scaled with shift_value^radix_stages.
OPTIONAL: pIn1 and pOut1 can point to the same memory location, pIn2 and pOut2 can point to the same memory location.
There are 4 stages for 128 and 256 input size buffers; 5 stages for 512 and 1024 input size; 6 stages for 2048 input size.
The twiddles and window coefficients are converted inside the used complex FFT kernel from q0.15 to q0.23 fixed point.

◆ RsdkBbe32Hist()

void RsdkBbe32Hist ( uintptr_t  argList)

Histogram 24bits real.

Performs Histogram on 24 bits 2 real inputs (data and edges).
It sorts data into bins with bin edges specified in the edges vector. The output values (expect the last two scalar values) represent how many input values respect the following inequation: edge(i) <= in < edge(i + 1); i=0...M-1.
The second last scalar value(int32_t) represents how many input values respect the following inequation: edge(M-2) <= in <= edge(M-1). The last scalar value(int32_t) is not useful data.

Parameters
[in]argList- pointer to a data structure of type rsdkBbe32HistParams_t containing the Histogram parameters and buffers.
Precondition
The pOut an pIn and pEdges are pointers to real output and input data which use int32_t.
The output are sign extended to 32 bits.
Values of the edges(threshold values) must be stored in ascending order.
The size(N) and sizeEdges(M) are restricted to being multiple of 16.
The useful output data has size equal to (sizeEdges - 1).

◆ RsdkBbe32OsCfar()

void RsdkBbe32OsCfar ( uintptr_t  argList)

1D OS-CFAR implementation across RDM 'range' dimension

Parameters
[in]argList- pointer to a data structure of type rsdkBbe32OsCfarParams_t containing the OS-CFAR parameters.

This function reads the input samples (from ORAM) and the sliding window thresholds (from ORAM) computed in the RsdkSptOsCfar kernel and then computes a new threshold vector.
The newly formed threshold vector is compared with the input samples element wise. If the sample is greater than the threshold the corresponding bit is set to 1 (1byte = 8 elements). Thre result is written back in ORAM.

Precondition
!!! THIS FUNCTION SHOULD ONLY BE USED INSIDE THE RsdkSptOsCfar KERNEL
The input is taken from ORAM and the output is written to ORAM.
The memory map is fixed. Input samples: OR_0_0_0, Input thresholds for BBE32: OR_2_0_0, Output: OR_0_0_0
If the memory layout is changed in the RsdkSptOsCfar kernel then RsdkBbe32OsCfar needs to be changed in the following way:
op_br0 - controls the bank selection for RLU0
op_br1 - controls the bank selection for RLU1
op_bw0 - controls the bank selection for WLU
RESTRICTION: op_br0, op_br1 and op_bw0 SHOULD POINT TO DIFFERENT CONTROLLERS
